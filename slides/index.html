01

The Foundation

CLAUDE.md + Git — teach your AI, protect your work.

CLAUDE.md — Your AI's Memory

A markdown file at your project root. Claude reads it at every session start.


# Fiscal Multipliers Project — CLAUDE.md

## Data
- Main dataset: `data/raw/state_panel.dta`
- Sample: US states, 1966-2006, annual

## Code Conventions
- Stata 18 for regressions, Python for cleaning
- Always cluster SEs at state level
- Use `reghdfe` for FE, never `xtreg`
- Tables via `estout` → `tables/`

## Key Variables
- Y: state GDP growth (`gdp_growth`)
- X: military spending share (`mil_share`)

Every correction you make → add to CLAUDE.md → Claude never repeats the mistake.

Why Git Matters

Safety Net

AI writes code. Sometimes wrong. git diff to review, git revert to undo. Instantly.

Context for AI

Claude reads git history — understands what changed, why, and the project state.

Collaboration

Share CLAUDE.md, skills, agents with co-authors. Everyone's AI learns the same rules.

Reproducibility

Every AI-assisted change tracked. Perfect audit trail for research integrity.

Rule #1: Never let AI edit files outside a git repo. No exceptions.

Data Validation Agent

A custom agent (not a skill) that autonomously validates datasets before analysis.


# .claude/agents/data-validator.md
---
name: data-validator
model: sonnet
tools: [Read, Bash, Write, Grep]
---

You are a meticulous data validator for econ research.

## Process
1. Read the dataset (.dta, .csv, .parquet)
2. Summary statistics for all variables
3. Missing values analysis (MCAR, MAR, MNAR)
4. Outlier detection (>3 SD)

5. Panel structure check:
   - Balanced? Gaps in time?
   - Duplicate id-time observations?
   - Within vs between variation

6. Write findings to data/validation_report.md
   - Pass/Fail summary at top
   - Code snippets to fix each issue

Skill Anatomy


---
name: summary-stats
description: Generate summary statistics tables
user-invocable: true
---

# /summary-stats — Summary Statistics Generator

## Arguments
$ARGUMENTS — path to the dataset file

## Instructions

### Step 1: Read the Data
Read the dataset. Detect format (.dta, .csv, .parquet).
Identify all numeric and categorical variables.

### Step 2: Compute Statistics
For numeric: N, mean, SD, min, p25, median, p75, max
For categorical: N, unique values, mode, frequencies

### Step 3: Generate LaTeX Table
Use booktabs style. Panel A: continuous, Panel B: categorical.
Include variable labels if available.

### Step 4: Save
Write to `tables/summary_statistics.tex`
Display a preview in the terminal.

# Each agent gets its own isolated copy of the repo
$ claude --worktree robustness "Run all IV robustness checks"
$ claude --worktree lit-review "Update the literature review"
$ claude --worktree data-clean "Clean the new Q4 data"

# No file conflicts — each works in its own directory
# When done, merge back via git

Why Worktrees Are Crucial

The Problem

Multiple agents editing the same files = merge conflicts and chaos. Agent 1 writes line 50 while Agent 2 deletes it.

The Solution

Git worktrees: same repo history, separate working directories. Each agent works in isolation. Changes merge cleanly.

~/my-project/
  ├── .git/                     shared history
  ├── main code...              you work here
  ├── .claude/worktrees/agent-1/ isolated copy
  ├── .claude/worktrees/agent-2/ isolated copy
  └── .claude/worktrees/agent-3/ isolated copy
"The single biggest productivity unlock — spin up 3-5 worktrees, each running its own Claude session." — Boris Cherny, creator of Claude Code
