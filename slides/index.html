CLAUDE.md — Teaching AI About Your Project

A markdown file at your project root. Claude reads it automatically.


# My Research Project — CLAUDE.md

## Project Overview
Estimating fiscal multipliers using regional variation
in military spending (Nakamura-Steinsson 2014 style).

## Data
- Main dataset: `data/raw/state_panel.dta`
- Instrument: `data/raw/military_contracts.csv`
- Sample: US states, 1966-2006, annual

## Code Conventions
- Stata 18 for main regressions (`.do` files)
- Python 3.12 for data cleaning (`src/clean/`)
- LaTeX tables via `estout` → `tables/`
- Always cluster standard errors at state level
- Use `reghdfe` for fixed effects, never `xtreg`

## Key Variables
- Y: state GDP growth (`gdp_growth`)
- X: military spending share (`mil_share`)
- Z: predicted spending from national contracts

Why Git is Crucial

Safety Net

AI writes code. Sometimes it's wrong. Git lets you git diff and git revert instantly.

Context for AI

Claude Code reads git history. It understands what changed, why, and what the project looks like.

Collaboration

Share CLAUDE.md, skills, and agents with co-authors. Everyone's AI learns the same conventions.

Reproducibility

Every AI-assisted change is tracked. Perfect audit trail for research integrity.

Rule #1: Never let AI edit files outside a git repo. No exceptions.

Skills

Reusable AI workflows you invoke with a slash command.

What is a Skill?

/lit-review
→
Skill Prompt
(SKILL.md)
→
Claude executes
multi-step workflow
  • A markdown file with structured instructions
  • Invoked via /skill-name in Claude Code
  • Turns complex, multi-step workflows into one command
  • Shared with your team via git
  • Lives in .claude/commands/

Boris's rule: "If you do something more than once a day, turn it into a skill."

Anatomy of a Skill guided example


---
name: lit-review
description: Search and summarize economics literature
user-invocable: true
---

# /lit-review — Literature Review Assistant

## Arguments
$ARGUMENTS — the research topic or question

## Instructions

### Step 1: Parse the Query
Extract the core research question, key terms,
and relevant fields from the user's input.

### Step 2: Search
Use Google Scholar MCP and web search to find:
- Seminal papers (most cited)
- Recent contributions (last 3 years)
- Working papers (NBER, CEPR, SSRN)

### Step 3: Synthesize
For each paper found, extract:
- **Key finding** (1 sentence)
- **Method** (IV, RCT, structural, etc.)
- **Data** (what and when)

### Step 4: Output
Write a structured lit review summary to
`notes/lit-review-{topic}.md`

Agents

Autonomous AI workers with specific roles and tools.

Skills vs. Agents

Skill /command Agent .md file
What A prompt template you invoke An autonomous worker with a persona
Where .claude/commands/ .claude/agents/
Invocation /skill-name Spawned as subagent or via --agent

Tools Uses main Claude's tools Can have custom tool set & permissions

Anatomy of an Agent guided example


---
name: data-validator
description: Validates and documents datasets
model: sonnet
tools:
  - Read
  - Bash
  - Write
---

# Data Validation Agent

You are a careful data validator for economics research.
Your job is to check datasets for common issues before
they are used in analysis.

## Your Process

1. **Read** the dataset (Stata .dta, CSV, or Parquet)
2. **Check** for:
   - Missing values patterns (MCAR, MAR, MNAR)
   - Outliers (>3 SD from mean)
   - Duplicate observations
   - Variable type consistency
   - Panel structure (balanced? gaps?)
3. **Document** findings in `data/validation_report.md`
4. **Flag** any issues that could bias estimation

## Important Rules
- Never modify the original data
- Always report summary statistics
- Compare with codebook if available

Why Git Worktrees? key concept

Problem: Multiple AI agents editing the same files = merge conflicts and chaos.

Solution: Git worktrees — each agent gets its own copy of the repo.

~/my-project/
  ├── .git/                 ← shared git history
  ├── main code...          ← you work here
  ├── .worktrees/agent-1/    ← agent 1's isolated copy
  ├── .worktrees/agent-2/    ← agent 2's isolated copy
  └── .worktrees/agent-3/    ← agent 3's isolated copy
  • Same git repo, independent working directories
  • No file conflicts between parallel agents
  • Changes merge back cleanly via git
  • This is how the Claude Code team at Anthropic works — 3-5 worktrees simultaneously

Worktrees in Practice

zsh — parallel agents with worktrees
# Create worktrees for parallel tasks
$ git worktree add .worktrees/clean-data main
$ git worktree add .worktrees/robustness main
$ git worktree add .worktrees/lit-review main

# Launch agents in parallel (separate terminals)
$ cd .worktrees/clean-data && claude \
  "Clean the state panel data, handle missing values"

$ cd .worktrees/robustness && claude \
  "Run all robustness checks for the IV regression"

$ cd .worktrees/lit-review && claude \
  "Update the literature review section"

# When done: merge results back
$ git merge clean-data robustness lit-review
