CLAUDE.md — Teaching AI Your Project

A markdown file at your project root. Claude reads it automatically at every session.


# Fiscal Multipliers — CLAUDE.md

## Data
- Main dataset: `data/raw/state_panel.dta`
- Sample: US states, 1966-2006, annual

## Code Conventions
- Stata 18 for regressions, Python for cleaning
- Always cluster SEs at state level
- Use `reghdfe` for FE, never `xtreg`
- Tables via `estout` → `tables/`

Key practice: Every time Claude makes a mistake, add a rule to CLAUDE.md.
Claude writes rules for itself and never repeats the mistake. Compound learning.

Why Git is Non-Negotiable

Safety Net

AI writes code. Sometimes wrong. git diff to review, git revert to undo. Instantly.

Context for AI

Claude reads git history — understands what changed, why, and the full project state.

Collaboration

Share CLAUDE.md, skills, agents with co-authors via git. Everyone's AI learns the same rules.

Reproducibility

Every AI-assisted change tracked. Perfect audit trail for research integrity.

Rule #1: Never let AI edit files outside a git repo. No exceptions.

02

Skills

Reusable AI workflows you invoke with a slash command.

What is a Skill?

/lit-review
→
Skill file
(markdown with instructions)
→
Claude executes
multi-step workflow
  • A markdown file with structured instructions for a specific workflow
  • Invoked with /skill-name — turns complex tasks into one command
  • Lives in .claude/commands/ — shared with your team via git
  • You can ask Claude to create skills for you

Rule of thumb: If you do something more than once, turn it into a skill.

Anatomy of a Skill


---
name: summary-stats
description: Generate summary statistics tables
user-invocable: true
---

# /summary-stats — Summary Statistics Generator

## Arguments
$ARGUMENTS — path to the dataset file

## Instructions

### Step 1: Read the Data
Read the dataset. Detect format (.dta, .csv, .parquet).
Identify all numeric and categorical variables.

### Step 2: Compute Statistics
For numeric: N, mean, SD, min, p25, median, p75, max
For categorical: N, unique values, mode, frequencies

### Step 3: Generate LaTeX Table
Use booktabs style.
Panel A: continuous variables
Panel B: categorical variables

### Step 4: Save
Write to `tables/summary_statistics.tex`
Display a preview in the terminal.

How to Build a Skill

Just ask Claude. It creates the file for you.

Claude Code
> Create a skill called /robustness that runs
  all IV robustness checks for my regressions.

✓ Skill created: .claude/commands/robustness.md

# Use it immediately
> /robustness analysis/main_iv.do

# Iterate — the skill evolves
> Update the /robustness skill to also check
  for weak instruments and add placebo tests

You never need to write markdown manually — Claude builds skills for you and refines them as you iterate.

03

Agents

Autonomous workers with specific roles and restricted tools.

Skills vs. Agents

Skill /command Agent .md file
What A prompt template you invoke An autonomous worker with a persona
Where .claude/commands/ .claude/agents/
Invocation /skill-name Spawned as subagent or --agent
Scope One workflow, then done Persistent role, can be long-running
Tools Uses main Claude's full toolset Custom, restricted tool set
Analogy A recipe card An RA with a job description

Anatomy of an Agent


---
name: data-validator
description: Validates datasets before analysis
model: sonnet
tools:
  - Read
  - Bash
  - Write
---

# Data Validation Agent

You are a meticulous data validator for econ research.
Your job: check datasets for common issues before
they are used in estimation.

## Your Process
1. Read the dataset (.dta, .csv, .parquet)
2. Summary statistics for all variables
3. Missing values analysis (MCAR, MAR, MNAR)
4. Outlier detection (>3 SD from mean)
5. Panel structure check (balanced? gaps? duplicates?)
6. Write findings to data/validation_report.md

## Rules
- NEVER modify the original data files
- Report exact variable names and counts

04

Worktrees

The key to running multiple agents safely in parallel.

The Problem with Parallel Agents

Multiple agents editing the same files = merge conflicts and chaos.
Agent 1 writes line 50 while Agent 2 deletes it.

The Solution: Git Worktrees

Same git repo, separate working directories. Each agent works in isolation.

~/my-project/
  ├── .git/                        shared git history
  ├── main code...                you work here
  ├── .claude/worktrees/agent-1/   isolated copy
  ├── .claude/worktrees/agent-2/   isolated copy
  └── .claude/worktrees/agent-3/   isolated copy

Worktrees in Practice

You can ask Claude to do this for you, or use the /worktree-planner skill to decompose a big task automatically.

Claude Code
> I need to run robustness checks, update the
  lit review, and clean the new Q4 data.
  Do all three in parallel using worktrees.

✓ Launching 3 parallel agents...
  Worktree 1: robustness checks
  Worktree 2: literature review
  Worktree 3: data cleaning
"The single biggest productivity unlock — spin up 3-5 worktrees, each running its own Claude session." — Boris Cherny, creator of Claude Code

Demo 3: Polish a Paragraph LIVE

Claude Code
> /polish
"We find that the fiscal multiplier is large and
statistically significant. Our results are robust
to many different specifications and we think this
is an important contribution to the literature."

Claude will:

  • Diagnose each sentence: vague claims, weasel words, missing magnitudes
  • Rewrite with precision, specificity, and proper academic tone

~30 sec. The fastest demo. Great for showing the writing quality.

Key Takeaways

  • Git is the foundation — all AI work must be version-controlled
  • CLAUDE.md is your leverage — teach the AI once, it compounds
  • Skills encode workflows — do it once, automate forever
  • Agents are autonomous workers — delegate and parallelize
  • Worktrees unlock scale — 3-5 agents working simultaneously

The compound effect: Every skill you build, every CLAUDE.md rule you add, every agent you create — they accumulate. Your AI gets better at your research every day.
