CLAUDE.md — Teaching AI Your Project

A markdown file at your project root. Claude reads it automatically at every session.


# Fiscal Multipliers — CLAUDE.md

## Data
- Main dataset: `data/raw/state_panel.dta`
- Sample: US states, 1966-2006, annual

## Code Conventions
- Stata 18 for regressions, Python for cleaning
- Always cluster SEs at state level
- Use `reghdfe` for FE, never `xtreg`
- Tables via `estout` → `tables/`

Key practice: Every time Claude makes a mistake, add a rule to CLAUDE.md.
Claude writes rules for itself and never repeats the mistake. Compound learning.

Why Git is Non-Negotiable

Safety Net

AI writes code. Sometimes wrong. git diff to review, git revert to undo. Instantly.

Context for AI

Claude reads git history — understands what changed, why, and the full project state.

Collaboration

Share CLAUDE.md, skills, agents with co-authors via git. Everyone's AI learns the same rules.

Reproducibility

Every AI-assisted change tracked. Perfect audit trail for research integrity.

Rule #1: Never let AI edit files outside a git repo. No exceptions.

Git in 90 Seconds — Your Undo Button

Git takes snapshots of your project. Each commit is a save point you can return to. That is the whole game.

1. Save before AI

git commit -am "before AI"
Snapshot exists. Everything after is reversible.

2. See what AI did

git diff
Every line added and removed. The highest-leverage 30 seconds in research.

3. Keep or undo

Good? git commit.
Bad? git checkout . — back to safe state. Zero damage.

A realistic afternoon
$ git commit -am "before robustness checks"
> Add 6 robustness checks to analysis/main.do
✓ 6 specifications added
$ git diff # one spec is wrong — wrong cluster variable
$ git checkout analysis/main.do # undo, safe state
> Redo, cluster by industry not firm. Explain why.

Memory & Plan Mode

How Claude remembers your project and thinks before it acts.

Three Layers of Memory

Claude loads all three at the start of every session. Each serves a different purpose.

1. Global CLAUDE.md

~/.claude/CLAUDE.md

You write it. System-level.
Applies to every project.
Your name, preferences, coding style, tools you always want used.

2. Project CLAUDE.md

<project>/CLAUDE.md

You write it. Project-level.
Applies to this repo only.
Data paths, variable names, SE clustering, estimation commands, co-author rules.

3. MEMORY.md

~/.claude/projects/<proj>/memory/

Claude writes it. Project-level.
Auto-saved by Claude as it works.
Patterns discovered, debugging notes, build commands it figured out.

CLAUDE.md = your instructions to Claude (like briefing an RA).
MEMORY.md = Claude's own notebook (the RA writing down what they learned). Both persist across sessions. Both are per-project (except global CLAUDE.md).

Memory in Practice

~/.claude/CLAUDE.md                      ← global: all projects
~/fiscal-multipliers/CLAUDE.md       ← project: this repo only
~/fiscal-multipliers/analysis/CLAUDE.md ← subdirectory: overrides for this folder
~/.claude/projects/fiscal-multipliers/memory/
  ├── MEMORY.md       ← auto-memory (first 200 lines loaded)
  ├── debugging.md   ← topic files Claude creates as needed
  └── patterns.md

Is Prompt Engineering Dead?

The old way

Craft elaborate prompts every session.
"Act as a senior economist, use formal tone, always cite sources, structure your output as..."
Fragile, repetitive, lost between sessions.

The new way

Design the system once:
CLAUDE.md rules + MEMORY.md learning + skills + agents.
Claude already knows your project, your style, your conventions.
Just say what you want.

Prompt engineering has moved from wordsmithing each request to designing the architecture around Claude — CLAUDE.md, skills, agents, memory. You engineer the system once; every session benefits.

Plan Mode — Think Before You Act

Claude enters read-only mode: explores the codebase, asks questions, builds a plan — but cannot edit anything.

Activate

Press Shift+Tab twice.
Or type /plan.
Claude switches to read-only exploration.

What Happens

Reads files, searches code, asks clarifying questions.
Outputs a structured implementation plan.
Press Ctrl+G to edit the plan.

Then Execute

Approve the plan, exit plan mode.
Claude follows the plan step by step.
Massively reduces wrong turns.

Boris's Workflow

Creator of Claude Code: "Start in Plan Mode, iterate until the plan is right, then auto-accept."

Anatomy of a Skill


---
name: summary-stats
description: Generate summary statistics tables
user-invocable: true
---

# /summary-stats — Summary Statistics Generator

## Arguments
$ARGUMENTS — path to the dataset file

## Instructions

### Step 1: Read the Data
Read the dataset. Detect format (.dta, .csv, .parquet).
Identify all numeric and categorical variables.

### Step 2: Compute Statistics
For numeric: N, mean, SD, min, p25, median, p75, max
For categorical: N, unique values, mode, frequencies

### Step 3: Generate LaTeX Table
Use booktabs style.
Panel A: continuous variables
Panel B: categorical variables

### Step 4: Save
Write to `tables/summary_statistics.tex`
Display a preview in the terminal.

Worktrees

The key to running multiple agents safely in parallel.

The Problem with Parallel Agents

Multiple agents editing the same files = merge conflicts and chaos.
Agent 1 writes line 50 while Agent 2 deletes it.

The Solution: Git Worktrees

Same git repo, separate working directories. Each agent works in isolation.

~/my-project/
  ├── .git/                        shared git history
  ├── main code...                you work here
  ├── .claude/worktrees/agent-1/   isolated copy
  ├── .claude/worktrees/agent-2/   isolated copy
  └── .claude/worktrees/agent-3/   isolated copy

Worktrees in Practice

You can ask Claude to do this for you, or use the /worktree-planner skill to decompose a big task automatically.

Claude Code
> I need to run robustness checks, update the
  lit review, and clean the new Q4 data.
  Do all three in parallel using worktrees.

✓ Launching 3 parallel agents...
  Worktree 1: robustness checks
  Worktree 2: literature review
  Worktree 3: data cleaning
"The single biggest productivity unlock — spin up 3-5 worktrees, each running its own Claude session." — Boris Cherny, creator of Claude Code

Integrations

Principles, not plumbing. Why each tool is worth the setup friction.

Why Integrations Matter

Claude is only as good as the context it can touch. Every integration exists because one principle of research workflow is broken without it.

Git

Reversibility. Every AI edit has an undo. Without git, AI is unsafe.

Overleaf

Plain-text source of truth. The paper must be editable by both humans and AI.

Obsidian

Memory outside the context window. A durable vault beats prompt stuffing.

Zotero

Citation integrity is a tooling problem, not a willpower problem.

Skip the integration and you lose the principle. Set it up once; benefit every session.

Obsidian — Memory Outside the Context Window

Your lit notes, seminar takeaways, half-baked ideas — a durable vault Claude can search, not re-derive.

The Problem

Context windows are finite. Pasting 200 papers' worth of notes into a prompt is wasteful and still will not fit.
Worse: every session starts with the same recap.

The Fix

Point the filesystem MCP at your Obsidian vault. Claude reads only the notes relevant to the current question.
Each session draws from the vault on demand.

Claude Code
$ claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/vault
> Find my notes on HANK models and summarize what I think is missing.
✓ Reads ~/vault/Notes/HANK/*.md, cross-references, returns synthesis

Principle: Durable memory (markdown on disk) beats ephemeral memory (what fits in one prompt). Your vault compounds; your context window resets.

Zotero — Citation Integrity as Tooling

Fabricated citations are the #1 AI failure mode in academic writing. The fix is not asking Claude to be careful — it is giving Claude the real .bib.

Why AI fabricates

Citations are plausible-looking strings. LLMs generate plausible strings.
Asking for "a citation on X" is asking for a hallucination.

The tool fix

Export Zotero to references.bib and point Claude at it.
Every \cite{} must match a real key — or fail visibly at compile.

Plus PDFs & annotations

Zotero stores the full PDFs. Claude reads them via /pdf-search instead of inventing summaries.
Your highlights become AI context.

Principle: Make hallucination impossible, not inadvisable. Citation integrity is a tooling problem, not a willpower problem.

Companion: Google Scholar MCP. Zotero grounds the papers you already have. Google Scholar MCP grounds what you are discovering — Claude issues real Scholar queries and returns real hits, not memorised strings. Install with claude mcp add google-scholar. Every "find papers on X" becomes a real search, not a hallucination.

Principles & Guardrails

What to internalize. Tools change; these do not.

Principle 1 — Compound Learning

Three files do the heavy lifting. Each session Claude gets smarter — not because the model improves, but because your system does.

CLAUDE.md

Who / what / how. Project context, conventions, coauthor rules. You write it.

MEMORY.md

An index. Points to per-topic memory files: debugging, patterns, style. Claude maintains it.

learnings/

Corrections. Each time you correct Claude, capture it as a durable learning. The mistake never recurs.

Compound effect: the PhD student who writes one learning per week has a system that — six months in — no longer needs to be told to cluster standard errors, use reghdfe, or check balanced panels. It just does.

Principle 2 — Critic / Fixer Separation

Never let an agent review its own work. A critic scores (read-only); a fixer applies changes. Five rounds with explicit scoring beats one-shot prompting.

Draft
→
Critic
read-only, scores
→
Fixer
applies corrections
→
Score ≥ 95
pass
  • Round 1: writing-test-suite — rules, magnitudes, active voice
  • Round 2: devils-advocate — hostile reading
  • Round 3: precision-auditor — logic + facts
  • Round 4: ai-audit — detect AI-telltale phrases, voice
  • Round 5: final gate — score ≥ 95 or loop back

Principle: Self-review has the same blind spots as self-writing. Separate the roles.

Principle 2b — Multi-Model Review

Claude's 5-round loop catches a lot. But a different model catches what Claude systematically misses — because it has different blind spots.

Claude
writes + self-reviews
→
Gemini
independent review
→
Codex / GPT
second opinion
→
You
decide
From inside Claude Code
$ gemini -p "Review this paper section for logic gaps" < sections/intro.tex
$ codex -q "Check this for fabricated citations" sections/intro.tex
# Or wrap it in a script:
$ bash gemini-validate.sh paper/main.tex prose
✓ Gemini review saved to paper/main.tex.gemini-review.md

Why different models matter: Claude does not flag its own AI phrases (it wrote them). Gemini has different training biases. Codex catches different logic gaps. The disagreements between models are where the real issues hide.

Principle 3 — Honesty Rule

TRUE > "I don't know" > FALSE.

  • Fabricated citation = auto-fail. Zero tolerance. One bad cite invalidates the draft.
  • Fabricated number = auto-fail. Same principle extends to coefficients, signs, percentages.
  • Verify against the raw log, not the summary. Claude writes "the effect is 2.3%." Open the regression output. Is it 2.3%?
  • Mark what is unverified. If a claim cannot be traced to a source on disk, tag it [UNVERIFIED] until it can.

Add this rule to your global ~/.claude/CLAUDE.md. It applies to every agent, every skill, every session — no exceptions.

Principle 4 — Durable State

Agents forget. Files do not. Keep your task list and project state in plain-text files Claude reads every session.

TASKS.md

Running list: priority, in-progress, completed, blocked.
Claude updates it as work completes — not at session end.
Same file readable by you, by cron, by any agent.

projects.json

A structured registry: status, stage, deadline, coauthors per project.
Dashboards and weekly plans read from it.
One source of truth for "what am I working on?"

Principle: If only Claude remembers it, it will be forgotten. Keep state in files you (and your agents) can re-read.

Principle 5 — Context Window Awareness Markus Academy

Goldsmith-Pinkham (Markus Academy, 29 Mar 2026): context-window management is the binding constraint on productivity.

Local, not web

Run Claude where it can touch files — IDE or terminal. Pasting code into a chat box loses filesystem, git history, and privacy.

Plan, then iterate

Do not one-shot. Break into steps: source → clean → structure → visualize. Iterate on what fails; do not restart.

Compress idea-to-first-result

Empty folder → scrape (SEC EDGAR, Census) → DuckDB → first chart. What used to take a week of RA time now takes an afternoon.

Watch the fuel gauge

Use /context to see window usage. /compact with focus ("keep the regression setup") before you hit the ceiling.

Risks & Guardrails

Non-negotiable for PhD students using AI on research. Break one and you damage something expensive — data, reputation, or co-author trust.

RiskGuardrail
Privacy / confidentiality
Unpublished data, co-author drafts, referee reports, proprietary datasets.		 Run Claude locally, not web chat with pasted text. Prototype on dummy data; plug in real data only once the pipeline is frozen.
Reproducibility
Code that ran once is not research.		 Treat AI scripts as code from a junior RA: version-controlled, re-run from scratch, outputs written to files that can be diffed.
Verification
AI paragraphs lie about numbers.		 Every coefficient, sign, percentage traces to a file on disk. Verify against the raw log, not the AI's summary.
Co-author coordination
Uncanny-valley edits confuse collaborators.		 Mark AI-assisted edits explicitly: commit tags, LaTeX comments, or a running note in the project CLAUDE.md.
Velocity vs. skepticism
50 tables in 5 minutes is not 50× the insight.		 High-velocity output demands high-velocity scrutiny. If you cannot read all 50 tables, you should not generate all 50.

Hooks — Quality Gates That Run Themselves

A hook is a shell command Claude runs automatically at specific moments. This is how you enforce quality without remembering to.

HookExample quality gate
SessionStart Load TASKS.md, surface this week's deadlines, re-inject the honesty rule.
UserPromptSubmit Inject "Never fabricate citations, data, or results" on every message.
PreToolUse Block writes to data/raw/. Refuse rm -rf. Require a commit before edits.
PostToolUse Auto-format after Python edits. Recompile LaTeX after .tex edits.
Stop Run the test suite, update TASKS.md, ping a macOS notification.

Why this matters for research: a quality rule only works if it fires every time. Hooks turn "I should remember to" into "it happens automatically." Configure with /hooks, or commit .claude/settings.json to share the gates with co-authors.

The Goal Posts Are Moving

AI is reshaping the publishing process — on both sides of the desk.

Refine.ink — $50/review

By Ben Golub (Northwestern). Referee-quality review in ~30 min.
Caught a sign error in a differential equation that human referees missed.
Cochrane: "Top 5% of reports I've read in 40 years."

53% of Reviewers Use AI

Nature (2025): majority of peer reviewers already use AI — often against journal policy.
EC 2026 offered Refine as free pre-submission feedback.

Andrew Ng's paperreview.ai

Free. Scores papers on 7 dimensions. Correlation with human reviewers: 0.42 (human-human: 0.41).
Less deep than Refine, but zero cost.

The Human Edge Remains

AI can't judge novelty, significance, or contribution.
It mistakes polished AI-generated papers for top-tier work.
Your economic intuition is the moat.

If reviewers use AI to find flaws, you should use AI to find them first.
The papers that survive will be the ones that were stress-tested before submission.

Claude for Your Learning — Three Modes

The use case most PhD students miss. Not teaching students — learning, yourself.

Private Tutor on Any Topic

"I have 2 hours. Teach me the continuous-time HJB/KFE approach from Achdou et al. (2022). Use the paper's notation. Quiz me every 10 minutes."
Grounded on the PDF via /pdf-search — no invented math.

Coding Partner on Replication

"Walk me through Local Projections on this dataset. Explain each step before you write it. Stop when I ask why."
You learn the method by typing, not copy-pasting.

Hostile Examiner

/devils-advocate on your own understanding.
"Drill me on the identifying assumption in Ottonello-Winberry (2020). Be hostile. I want flyout-grade pressure."

The test: if you cannot defend on a job-market flyout the math that AI wrote into your paper, you failed the exercise — regardless of whether the paper got written. Use AI to steepen your learning curve, not to skip it.

Talk With the Greats grounded personas

Not a parlour trick. Point Claude at the actual writing and let it respond in that voice, that framework, that set of priors. You learn a tradition by conversing with it.

Friedman vs. Keynes on a Shock

"Read Friedman (1968 AEA) and General Theory ch.13–15 from the PDFs in ~/vault/Classics/.
Now respond to the 2020 fiscal stimulus from each perspective in turn. I will moderate."

Steelman Lucas on the Phillips Curve

"Use Lucas (1972, 1976). I will argue the curve is stable. Attack my argument using only Lucas's own reasoning — no anachronisms, no post-1980 evidence."

Seminar Q&A Rehearsal

"You are the most hostile referee on my paper drafts/jpe_r1.pdf. Ask the 5 questions you would ask at a seminar. Wait for my answer before the next one."

Reading-Group Facilitator

"Pick 3 genuine disagreements between Hayek (1945) and Stiglitz-Greenwald (1986) on information. Make each case in turn — then let me decide who is right."

Why grounding matters: without a PDF, "talk to Friedman" is an impression. With Friedman's actual papers in the context, it is Socratic dialogue with a tradition. Combine with Zotero + /pdf-search; refuse quotes that are not in the source.

Key Takeaways

  • Git is the foundation — all AI work must be version-controlled
  • CLAUDE.md is your leverage — teach the AI once, it compounds
  • Skills encode workflows — do it once, automate forever
  • Agents are autonomous workers — delegate and parallelize
  • Worktrees unlock scale — 3-5 agents working simultaneously

The compound effect: Every skill you build, every CLAUDE.md rule you add, every agent you create — they accumulate. Your AI gets better at your research every day.
